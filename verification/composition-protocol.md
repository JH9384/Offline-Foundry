# Generated composition protocol evidence

FA-07 implements `CompositionProtocol.boundary` and `adapterBoundary` in
`app/src/CompositionProtocol.lex.tex`. The existing generated byte-dispatch guest
now accepts a bounded composition request, decodes it in LexLean, calls
`FeatureComposition.admitComposition`, and returns the modeled outcome. Existing
phase and permission requests retain their existing 64-byte limit and behavior.

The protocol uses unsigned 32-bit little-endian representation values and
length-prefixed lists. Limits are 16,384 payload bytes, 32 features and 64 entries
per list. Truncated, excessive-count and trailing data refuse. The expanded guest
request/allocation bounds are declared in the application model. All semantic
admission remains in the generated guest; the browser module only encodes the
wire representation and decodes known responses from a caller-supplied guest.

## Evidence

Registration, scenario and failing test preceded implementation. Eight guest
acceptance vectors are independently recorded in `composition-wire-vectors.json`
and pinned to the actual application model by the executable codec suite. The
complete SDK `prismpm verify` gate replays those vectors in the compiled guest;
local source checks and mocked dispatch do not substitute for that replay.

Seven Node tests cover byte-for-byte encoding, invalid scalar representations,
exact record fields, list/payload limits, all semantic refusal codes, invalid guest
responses and runtime errors. The adapter tests make no inference that a mocked
guest establishes runtime conformance. Changing endianness caused two failures;
forging acceptance for every response caused two failures. Both mutations were
restored. All 41 local Rust workspace tests passed, including the codec controls,
and every shell module parsed under its browser goal.

Diagnostic LexLean verification accepted seven modules with attestation
`19aec6d2ea9b9d42cda57c1f7997812003ed48816e92f88c35915dda8defa8f5`.
The compiler differs from the lock, so remote locked-SDK verification remains
required. No SDK, template lock, universal gate or vendor implementation changed.

## Completeness review

Author review checked header and field order, scalar endianness, list limits,
truncation/trailing refusal, producer tuples, cumulative admission invocation,
legacy dispatch preservation and acceptance-vector reachability. This is a
self-review, not independent approval. A caller must supply the appropriate
verified guest; this adapter does not fetch or authenticate it. Registry/UI
integration, intent routing and whole-product release acceptance remain separate
specification obligations.

The first SDK attempt rejected the application declaration because the changed
input-allocation bound lacked an exact-boundary vector (PP2009). The bound is
16,400 bytes and the corpus now includes a 16,400-byte request that must return
compositionTooLarge. This field limits guest input allocation, not overall heap
use; it is distinct from the composition contracts' declared resource budgets.
